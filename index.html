About

I started in 2008 resolving IT and security tickets. Today I lead GRC engineering for the Commonwealth of Virginia, building the program from the ground up for 67 state agencies and 8.8 million residents.

In between, I spent years in DoD RMF as an ISSO, ISSE, Acting ISSM, and Security Control Assessor on Army PEO STRI programs. I learned the work from both sides of the table, and over time I became the go-to SME when an authorization was in trouble: an expired ATO, a denied ATO, a system stuck on an IATT, a software release about to slip.

Those programs taught me that most compliance pain comes from manual work: evidence pulled by hand, spreadsheets nobody trusts, documents out of date the day they’re signed. So I build compliance as code with Python, Terraform, OSCAL, and CI/CD pipelines that generate evidence instead of chasing it, and I share the tools on GitHub.

I founded the Central Florida chapter of the GRC Engineering Club and taught cloud security at Seminole State College, where I sat on the industry advisory board.

Lifecycle

I’ve worked every step of NIST 800-37 as both the control implementer (ISSO, ISSE, and Acting ISSM) and the control assessor. The repos under each step are open-source tools I built on my own to automate that work, and rmf-toolchain connects them into one pipeline that covers all 7 steps.

01
Prepare

Set roles, boundaries, and risk strategy with system owners and Authorizing Officials, and check the declared boundary against what actually exists in AWS.boundary-drift-detector

02
Categorize

Set impact levels under FIPS 199 and CNSSI 1253 from NIST SP 800-60 information types, and select the matching control baseline.security-categorizer

03
Select

Tailor NIST 800-53 baselines, overlays, and inheritance, and map CMMC practices to NIST and AWS controls.cmmc-control-mapper

04
Implement

Ship controls as code with Terraform, block insecure changes in CI/CD with tfsec, Checkov, and OPA policy checks, and document the implementation in OSCAL.cloud-governance-platform · oscal-ssp-generator

05
Assess

Run independent assessments with ACAS, SCAP, and STIG tooling, write SARs and RARs, and automate scan ingestion and control scoring.cmmc-scorecard · fedramp-control-validator

06
Authorize

Quality-check every package in eMASS, run automated readiness checks on the OSCAL package, and brief leadership on risk so the Authorizing Official can decide.ato-readiness-checker

07
Monitor

Run continuous monitoring: track POA&Ms and vulnerabilities, report FISMA metrics, and turn STIG checklists, ACAS scans, and AWS Security Hub findings into POA&Ms automatically.stig-poam-builder · poam-generator · continuous-monitoring-dashboard

rmf-toolchain

One system, every RMF step, one push. Seven of my tools hand off OSCAL documents: categorize, baseline, SSP, boundary check, assessment, POA&M, readiness, and day-30 monitoring. Every document is checked against NIST’s schemas, and the full package downloads from each CI run.

ato-readiness-checker

Catches what gets a package sent back before the AO sees it: an SSP that says “implemented” when the assessment says “not satisfied,” weaknesses with no POA&M item, overdue or ownerless POA&M items. 30 checks, a readiness report, and a one-page draft AO brief that leaves the decision blank.

Python · OSCAL · Authorize · 178 tests, 97% coverage
GitHub ↗

security-categorizer

Categorize and Select for federal and national security systems. In NSS mode, C, I and A each pick their own CNSSI 1253 column, so an H-M-L system gets 543 controls instead of a high-water mark’s 607. The baseline data is extracted by script from the user’s own copy of CNSSI 1253 and checked against NIST SP 800-53B.

Python · CNSSI 1253 · OSCAL 1.1.2 · 124 tests, 99% coverage
GitHub ↗

boundary-drift-detector

The SSP inventory is approved once; the cloud account changes daily. This compares the two and catches what nobody declared or assessed: public buckets, open security groups, unencrypted databases, leftover servers. Anything it can’t confirm is reported as unverified.

Python · AWS Config · CM-8 · 102 tests, 99% coverage
GitHub ↗

stig-poam-builder

Turns DISA STIG checklists (.ckl/.cklb) and ACAS scans (.nessus) into eMASS-style POA&Ms, OSCAL 1.1.2, and CSV, mapping findings to NIST 800-53 Rev 5 through DISA CCIs. One item per weakness, stable IDs for month-to-month diffs, and hardened XML parsing.
